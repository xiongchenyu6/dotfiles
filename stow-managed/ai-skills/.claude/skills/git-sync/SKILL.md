---
name: git-sync
description: 修复 git pull 或 push 因本地未提交改动、分叉、fetch first 或 flake.lock 冲突被拒绝的问题。
---

1. 检查当前分支、工作区与暂存区，fetch 后查看两侧提交。已有 merge 或 rebase 时先识别其状态，避免叠加操作。
2. 用户只要求同步时，保留暂存边界。用带说明的 stash 保存改动，记下其对象 ID；同步后用 `git stash apply --index <id>` 恢复。若用户也要求提交，把已验证、属于本次任务的改动按主题提交。
3. 远端领先时 fast-forward。双方分叉且本地提交未发布时可 rebase。不要 force push。
4. 对 `flake.lock` 按输入节点合并，比较共同基线、本地、远端。新增固定输入要保留节点及根输入映射。如果两边更新同一输入，先验证提交祖先关系，再选包含双方历史的版本。显式版本固定或上游分叉不能按时间戳裁决。避免无关输入更新。
5. 检查无冲突条目、工作区和暂存区符合预期、领先与落后计数准确。仅当任务包含推送时执行普通 push。验证完成后报告提交、未提交改动及备份位置。
