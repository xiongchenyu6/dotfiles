# 长任务托管

## 起任务

- 长任务不要前台裸跑:`nohup … > /path/log 2>&1 &` 或
  `systemd-run --user --unit=<name> …`(能用 systemd 就用,方便查状态和自动重启)
- 日志必须落文件,路径当场告诉用户
- **本机要关机/性能不够就放算力机跑**(编译、CUDA、批量生成一律往 sg-office 这类
  机器扔),别占着用户的桌面机
- **能并行就并行**:按模块/按数据分片/按关卡拆,多个后台任务同时跑,不要串行干等。
  独立子任务用 subagent 并发推进

## 盯任务

- 定时检查:进程活着没、日志尾部有没有报错、产出是否在增长
- 可预期的失败(OOM、网络闪断、依赖临时挂、hash 变化)直接修复后续跑,
  **不要停下来等人**
- 修不了的失败:保留现场(日志尾部 + 复现命令),汇报后再等指示
- 用户说"我去睡了,你 loop 盯着":用 `/loop` 自定节奏挂住,每轮做**实质推进**
  (跑下一轮验收、修上一轮暴露的问题),不是每轮只打印一句"还在跑"

## 进度汇报格式(被问"啥进度了"时)

一句话说清:**阶段/百分比 + ETA + 最近一条关键日志**。
例:「3/5 个模块编译完,预计还要 20 分钟,当前在 link libfoo」。
不要只回"还在跑",也不要为了回答去重跑一遍任务浪费 token。

## 收尾

任务结束(成功或失败)主动汇报:结果、产物路径、日志路径、下一步建议。
产物要过验收(测试输出/截图/manifest),没验证过就明说未验证。
