# 游戏打磨循环(Bevy / WebGPU)

## 目标水准

「可发售的单机游戏」——不是能玩就行。每轮打磨都对照这个标准,不要问"够不够",
不够就继续下一轮。

## 核心循环:截图 harness

1. 把游戏跑起来(WebGPU 需要 Chrome/Edge 113+;优先全屏,不要窗口小字提示)
2. 用浏览器自动化多截图:**不同交互状态各来一张**——待机、选中、施放、
   受击、结算。单张静态图发现不了反馈缺失类问题
3. 对着截图列体验问题清单,按玩家感知排序,逐条修
4. 修完重新截图对比,确认修复且无回归,再进下一轮

## 高频体验问题清单(历史踩过的坑,每轮都查)

- **反馈缺失**:下达指令没有表示(如右键攻击无指令确认、无攻击特效)。
  每个玩家操作都必须有即时视觉/音效反馈
- **UI 遮挡**:快捷栏/面板挡住可交互区域(格子、单位)。UI 高度收小,
  或交互区避开
- **HUD 可读性**:血槽太细、字太小。以"一眼扫到"为标准
- **素材问题**:贴图重影、地图拼接错乱、比例失调。截图放大逐块检查。
  缺素材不要凑合,批量生成(见 comfyui-assets skill),精灵图要带动画帧
- **UI 用文字凑数**:UI 一律用 icon/图形,不用文字标签(击杀数用骷髅头、
  资源用图标)。没有 icon 就去生成,不要退回文字
- **触屏/移动端**:选中后必须能取消选中;考虑拖动式建造;点击目标别太小;
  状态栏/提示浮层不得遮挡棋盘和操作区,提示用半透明、可自动消失
- **玩法单一**:技能/特效数量和多样性直接决定耐玩度。宁多勿少,做出量级
  (几十上百种),再筛
- **节奏**:重随机性、重剧情,轻练级。玩家不想刷,别设计成要刷

## 原则

- 每轮只聚焦一个维度(反馈 → UI → 素材 → 玩法),别撒胡椒面
- 体验问题用玩家语言描述("点了没反应"),不用实现语言("事件没派发")
- **修 bug 流程是硬规定**:harness 复现问题 → 修 → harness 截图确认修复且
  无回归,然后才能说"已修复"。没有截图证据的"已修复"一律视为未修复
