# 游戏打磨循环(Bevy / WebGPU)

## 目标水准

「可发售的单机游戏」——不是能玩就行。每轮打磨都对照这个标准,不要问"够不够",
不够就继续下一轮。**不要停下来问优先级,剩余项一起并行做完再汇报。**

## 核心循环:截图 harness

1. 把游戏跑起来(WebGPU 需要 Chrome/Edge 113+;必须全屏,不要窗口小字提示)
2. 用浏览器自动化多截图:**桌面 + 手机两套视口,各交互状态各一张**——
   待机、选中、施放、受击、结算、弹窗。单张静态图发现不了反馈缺失类问题
3. 对着截图列体验问题清单,按玩家感知排序,逐条修
4. 修完重新截图对比,确认修复且无回归,再进下一轮

## 三条硬规定(违反等于没做)

- **修 bug**:harness 复现 → 修 → harness 截图确认修复且无回归,才能说"已修复"。
  没有截图证据的"已修复"一律视为未修复
- **文字一律换 icon**:UI 里任何文字标签都是待办项(击杀数用骷髅头、资源用图标、
  快捷栏用图标、关卡选择用地图缩略图)。文字信息塞进 tooltip。没有 icon 就去生成
  (见 asset-gen skill),不要退回文字
- **每个可点元素都要 tooltip**:塔、技能、天赋、职业、种族、装备、图鉴条目、
  战役进度图标。手机端 tooltip 走长按/预览,不能"点一下就直接买入/直接建成"

## 移动端布局(踩最多坑的地方,新功能一律先按这个设计)

- **棋盘/战场格子是核心体验,任何 UI 都不许遮挡它**。上下状态栏尤其糟——
  改成左右侧栏(左右手都够得着)
- **布局顺序:先渲染左右侧栏,用剩余空间算棋盘尺寸**。不要先摆棋盘再叠 UI,
  那样永远在修遮挡 bug
- **必须有全局 mobile/desktop 判定变量**,分支逻辑统一读它,避免"手机能选中、
  电脑选不中"这类分裂 bug
- 选中后必须能取消选中(否则建完塔点不了"开始波次")
- 选塔后放格子前要有**范围预览**,不能点一下直接建成
- 侧栏/塔列表在手机上要能滑动;虚拟摇杆用圆形,按压屏幕才出现,不常驻
- Boss/波次提示浮层:放正上方、半透明、自动消失,不要黑底大方块盖住入口和英雄
- 同一功能不要上下各来一个按钮(开始按钮重复、血量金币左右重复)

## 加载与 Web 交付

- **主程序 + 资源都下完才允许进入战场**,不要"15 秒保底"放行——玩家进去是空的
- 加载条显示真实分项进度(引擎 wasm / 资源包 各自 MB 数),不要笼统一句
  "Loading defenses…"
- **引擎与游戏资产分包**:引擎 wasm 大且不常变,单独缓存;游戏逻辑资产小、常更新
- 传输开 brotli(改完要实测确认没退回未压缩);贴图用 webp 不用 png
- 发布 wasm + GitHub Pages;大资源走 git-lfs

## 高频体验问题清单(每轮都查)

- **反馈缺失**:每个玩家操作都要有即时视觉/音效反馈(指令确认、命中特效、
  全屏技能如陨石/爆金币要有动画)
- **精灵图不合格**:静态图平移、只有残影、走路手脚不动、旋转着位移 = 不合格。
  一个动作 ≥8–10 帧;近战职业要劈砍动作,不能变成远程投射;每种怪物要有
  受击/攻击动作。背包里的装备图必须和角色身上的一致
- **HUD 可读性**:血槽太细、字太小。以"一眼扫到"为标准
- **素材问题**:贴图重影、地图拼接错乱、比例失调、未解锁关卡显示成灰方块。
  截图放大逐块检查,缺素材批量生成
- **内容深度**:图鉴(怪物/英雄/技能/装备,打过就解锁)、职业与种族差异化
  (射程/攻击方式/发展路线各不同)、每职业 30 级终极技能、精英词缀
  (飞行/隐身/冲锋/吞塔/孵化,各分等级)。数量和多样性直接决定耐玩度
- **新手引导**:第一次玩要有试炼关卡,一步步指到点哪里
- **节奏**:重随机性、重剧情,轻练级。玩家不想刷,别设计成要刷

## 原则

- 每轮只聚焦一个维度(反馈 → 移动端 → 素材 → 内容 → 平衡),别撒胡椒面
- 体验问题用玩家语言描述("点了没反应"),不用实现语言("事件没派发")
- 数值平衡不靠拍脑袋,用 headless 模拟跑胜率(见 game-balance-sim skill)
- 素材生成见 asset-gen skill;长时间编译/批量生成挂后台见 long-task-babysit
