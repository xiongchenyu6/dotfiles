# Autolife 文档惯例

## 飞书操作

- 读写飞书 wiki 用 `lark-cli`
- 新建文档默认开全公开权限(除非明确要求内部)

## 文风要求(反复被纠正过的点)

- **主线要讲清楚**:文档先把"是什么、为什么、怎么用"的主线铺完,
  技术细节放后面或附录——不要把关键内容折叠成小字技术细节
- **以读者可上手为验收标准**:部署/测试文档写到「测试工程师实习生
  拿着文档就能对真实机器人操作」的粒度——每步有具体命令、预期输出、
  失败时的排查方向
- 风险类文档要把"其他风险测出来"当目标写测试步骤,不是罗列理论风险

## 组件对接

组件清单以本地 `~/Documents/github/autolife/` 下的各仓库为准。
新组件设计必须说明与已有组件如何对接,不能孤立设计——写对接文档前
先扫一遍该目录确认最新组件集合。

## 部署环境

- 内网:gz-office(SSH 用名字直达)
- 云端:huoshan-bj-001(autolife 相关服务的归属机);对外服务域名
  见 ansible 目录下对应的 inventory
