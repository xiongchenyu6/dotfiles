# 设计红线(KISS)

出方案前先过一遍这张表。历史上被打回的方案 90% 都栽在这里。

## 先问四句

1. **这个组件能不能删掉?** 能删就删,不要"先留着以后可能用"
2. **数据能不能就放 git?** 配置/版本/编排信息优先 CUE/JSON/YAML 进仓库,
   CI 编译成产物,页面直接加载。**不要为了存几十条配置上一个数据库**
3. **上游有没有现成的?** nixpkgs / 官方镜像 / 已有 flake input 里有就直接用,
   不要自己打包、自己造轮子、自己写用户体系
4. **是不是在给不存在的场景做兼容?** 没上线 = 没有历史包袱 = 不做向后兼容,
   直接做成最终形态

## 常见过度设计(直接否)

| 过度 | 该做的 |
|---|---|
| 上数据库存配置 | CUE/JSON 进 git,CI 编译,前端直接读 |
| 自建用户/权限体系 | 统一 SSO(casdoor),身份和角色从 group claim 映射 |
| 引入一整套 BaaS 只用其中一个组件 | 只留真正用到的那个(如只留 postgrest),其余全删 |
| 为了鉴权塞一层 edge function / deno 容器 | 直连 + SSO token 或 mTLS,少一层是一层 |
| 服务端主动推给设备 | **pull 模型**:设备主动来拉、主动上报,服务端不关心设备在线状态 |
| 每个功能一个二进制 | 一个 CLI + 一个 TUI 就够 |
| 上强化学习/训练解决调参 | 先用 greedy + 二分搜索 |
| 加一层兼容 shim 保旧字段 | 删旧字段,一次改到位 |
| 容器化一切 | 能 systemd/二进制就别 docker |
| 用 ansible 管 NixOS 机器 | `nixos-rebuild` |

## 重构时

- **不留向后兼容**:旧字段、旧代码、过渡设计痕迹、废弃文档、遗留目录、
  没用的分支——全部删掉,不要注释掉、不要移到 legacy/
- "遗留着不是造 bug 么" 是默认立场:纯测试期的数据库可以直接 drop 重建,
  SQL 可以合并整理
- 边界收敛后要**重新描述这个项目的职责**,不属于本职责的内容(别的项目该管的)
  从代码和文档里搬走
- 清理完顺手把文档同步到只剩最新设计(见 autolife-docs skill)

## 交付形态红线

- 不给最终用户看裸 API 页面 / Swagger,必须有 proper 前端
- 对外界面单一语言(默认全英文),不中英混杂
- 运营要能自己改的内容走可视化编辑,不要硬编码
- 给别人用的安装/升级入口收敛成**一条 curl 命令**,且能自检并修复损坏的旧安装
