# 数值平衡:headless 模拟,不拍脑袋

手调数值 → 自己玩两局 → 感觉差不多,这条路不成立。平衡必须能被跑出来、
被复现、被对比。参考实现:`protect-carrot` 的 `src/bin/sim.rs`。

## 模拟器的硬要求

- **复用真实游戏系统**,不另写一套简化模型——否则调出来的数在真机不成立。
  Bevy 里就是加载 lib crate 的 systems,只去掉渲染/窗口/GPU
- **确定性**:固定步长(`TimeUpdateStrategy::ManualDuration`,1/60s)+ 显式 seed。
  同 seed 同结果,否则没法比较两次改动
- **有超时上限**(最大帧数),防止卡死的局把整轮 sweep 拖住
- 环境变量开关关掉干扰项(如 `*_SIM_NO_HERO` 单独测塔),便于分离变量

## 分层做法(逐层加深,别一上来就做优化器)

**Layer 1 — 谁强谁弱**
- `iso` 模式:每种塔单独铺满棋盘各跑一局,看**独立通关能力**
  (总伤害、伤害/金币、胜负、撑过几波)。这是公平口径
- `mixed` 模式:所有塔混合上场看伤害占比。注意这是"击杀记功",
  偏袒爆发塔,DoT/减速塔会被低估——**不要用 mixed 判定塔弱**

**Layer 2 — 会玩的 AI 打给你看**
- 写 greedy player:用真实经济(靠击杀金币建塔+升级),每隔几帧挑当前
  收益最高的一手。要点:
  - 建塔要铺开覆盖,不要堆一处
  - 升级和新建同池竞价(比 `当前收益 × 优先级 / 造价`)
  - 对隐身/飞行等要有反应式应对(该出侦测塔就出)
  - 决策频率按游戏时间而非帧数,这样 4× 速跑 sweep 不会削弱 AI
- `winrate` 模式:单关 N 个 seed 跑胜率;greedy 越聪明,结论越接近真人上限
- `all` 模式:全关卡 sweep → **难度曲线**。异常关(比如某关胜率断崖、
  第 1 波就被墙死)单独拎出来查,别在曲线上一把梭调整

**Layer 3 — 逐关经济优化器**
- 对每关二分搜索(起始金币, 击杀奖励),让 greedy 胜率贴合目标曲线
- 输出推荐值 → **烘成数值表写回 levels 定义** → 再跑一次 all sweep 复核
- 复核通过才提交;数值表和 sweep 输出一起提交,方便下次对比

## 工作节奏

```
改数值 → 跑 winrate(改动关) → 跑 all(全曲线,防串扰) → 看曲线 → 再改
```

- 每次汇报带**曲线本身**(每关胜率/超时/平均存活波数),不要只说"平衡了"
- 目标曲线先定下来再调(例:前 5 关 90%+、中段 60–75%、Boss 关 40–55%)
- 塔改动后必跑 `iso`,确认没把某塔调成废物或超模
- sweep 是长任务,挂后台跑并定时汇报(见 long-task-babysit skill)

## 别做的事

- 别用强化学习/训练框架解决"塔平衡"——greedy + 二分搜索已经够,
  引入训练是过度设计
- 别只测一个 seed;别用 mixed 占比下结论;别跳过烘表后的复核 sweep
